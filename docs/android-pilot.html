Use your existing Tejasvi installation

This download contains the existing web application, the new mobile API, the Android source and a testing APK in one project folder. It does not create a separate mobile database or institution.

The first test uses your Mac and a USB-connected Android phone. Keep MySQL, Tejasvi and the USB connection running. This is a local pilot; the current server launcher accepts localhost only. Remote school testing will need a separately configured HTTPS deployment.

1. Update the server you already use

  1. In the Terminal window running Tejasvi, press Control+C. Leave MySQL running.
  2. Open Terminal in your original configured Tejasvi Campus 3.9.0 folder and run npm run backup. Keep that backup before updating.
  3. Unzip Tejasvi-Campus-3.10.0.zip. In this new download, open Update-Tejasvi.command.
  4. When Finder asks for a folder, select your original configured project—the one you normally launch.
  5. Open Start-Tejasvi.command in the original folder. Wait for Tejasvi is ready: http://localhost:3000. The launcher rebuilds the application and adds the device-session table to your existing database.
  6. Open the mobile API status in your Mac browser. It should show "version":"3.10.0" and "mobileApi":1.

Do not run a new institution setup for this update. Your accounts, records, uploaded files and AI settings stay in the original installation. The updater accepts the verified 3.9.0 source, can run again on 3.10.0, and stops before changing files if it detects a local edit or unsupported version.

If you deliberately want a completely new installation, use Start-Tejasvi.command in the new folder and follow its existing MySQL setup. That creates a blank institution environment; it will not contain your current users or courses.

2. Prepare the Android connection

  1. On your Mac, open Google's SDK Platform-Tools download page, choose Mac, and unzip the download. Leave the folder at Downloads/platform-tools. If you already use Android Studio, its installed Platform-Tools also work.
  2. Use an Android phone running Android 8.0 or newer. Enable Developer options, then USB debugging. The setting's location varies by phone; use Google's device setup instructions if needed.
  3. Connect the phone to the Mac with a USB data cable. Unlock it and accept Allow USB debugging for your Mac.
  4. Keep exactly one Android phone or emulator connected. In your updated project, open Test-Android-USB.command.

The helper checks the server, installs android/pilot/Tejasvi-Android-Pilot.apk, connects the phone to the Mac's port 3000, and opens Tejasvi Pilot. It never uninstalls an existing app automatically.

You do not need to compile Android source to run the included APK. Android Studio and a JDK are needed only if you want to change the code or build your own APK.

3. Sign in on your phone

FieldWhat to enter
Campus server addresshttp://localhost:3000
Email addressThe same student, employee, teacher or administrator email used on the website.
PasswordThat account's existing password. A temporary password must be changed on first sign-in.

If the account belongs to several institutions, open Account → Switch institution. Course access follows the selected institution and the same batch or intake assignment used on the web.

The USB connection maps the phone's localhost to your Mac. After unplugging and reconnecting, run Test-Android-USB.command again. Entering your Mac's Wi-Fi address will not work with this local server configuration.

4. Test the complete learning loop

Student or employee

  1. Open Learning and choose an assigned course.
  2. Read a lesson or unit and select Mark as read.
  3. Complete a course or unit quiz.
  4. Open Tasks. Write an answer and optionally attach a PDF, DOCX or PPTX up to 5 MB.
  5. Submit. Confirm Awaiting feedback appears.

Teacher

  1. Sign in with the assigned teacher account, on the web or another phone.
  2. Open Tasks → Awaiting review.
  3. Read the student's answer and attachment.
  4. Release a mark with feedback, or return the work with a revision deadline.
  5. The learner refreshes Tasks or Progress to see the same update.

Verify the result on the website as well. Reading completion, quiz attempts, submissions and grades are stored in the same MySQL records.

Before sharing more widely: try this on your own physical phone, including a large text setting, rotation, interrupted Wi-Fi and reconnecting USB. The supplied automated checks do not replace a real device acceptance test.

For your developer

Open android/ in Android Studio. Source uses Kotlin, Jetpack Compose, JDK 17+, SDK 36 and the versioned /api/mobile/v1 API. Build-Android.command builds and places the testing APK in the pilot folder.

Access tokens last 15 minutes; rotating refresh tokens have a 30-day absolute expiry. Server-side hashes link device sessions to existing password resets. Device credentials and drafts use Android Keystore encryption. Signing out removes local drafts and downloads.

The supplied APK is debug-signed for testing, not a Play Store release. A production release needs hosted HTTPS, production signing, device testing and a store/privacy review. No provider subscriptions, live generation charges, hosting or store publication are triggered by this package.

See android/README.md for API details and docs/android-validation.md for the exact validation performed.
