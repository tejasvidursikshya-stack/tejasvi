# Tejasvi native Android pilot

Kotlin + Jetpack Compose. The app uses `/api/mobile/v1` in the parent Tejasvi project. MySQL records, identity, course access and grading rules remain on that server. No demo account, database credential or AI provider key is embedded in Android.

## Test on a Mac and Android phone

1. Follow `../docs/android-pilot.html` to update the **original configured 3.9.0 installation** to 3.10.0. Keep MySQL and Tejasvi running on the Mac.
2. Download Google’s SDK Platform-Tools for Mac and unzip to `~/Downloads/platform-tools`, or use the tools installed by Android Studio. Connect one Android 8.0+ phone with a USB data cable. Enable USB debugging and accept that Mac on the phone.
3. Open `../Test-Android-USB.command`. It checks the mobile API, installs the included testing APK, forwards the phone's localhost:3000 to the Mac and opens the app.
4. Sign in at `http://localhost:3000` using the existing learner or teacher account. The localhost HTTP exception exists only in the debug pilot; other HTTP hosts are refused.

This installation is a local pilot. The current server launcher deliberately accepts only localhost. A remote school pilot needs a separate hosted HTTPS deployment change and deployment review; entering a public URL in Android alone does not publish this server.

## Implemented native workflow

- Existing account login, first-use password change, organization switching and sign-out.
- Assigned published courses, lessons and units; completion updates to MySQL.
- Course and unit quizzes with stale-version checks.
- Protected course files and assignment question files, opened in an installed PDF/Office viewer. Video links open an installed browser or video app.
- Assignment answers, optional HTTPS link and PDF/DOCX/PPTX attachment up to 5 MB. Encrypted local text drafts, explicit online submit, revision conflict messages.
- Teacher/admin review, release grades and feedback, return work for revision with 3/7/14-day deadlines.
- Learner progress and feedback, teacher scoped progress, approved results displayed read-only.
- The website remains the place for course authoring, enrolment, institution settings, EMIS and final result approval/export. Native AI, flashcards, push, offline lessons, live classes, parent access, administration and iOS are later milestones, not hidden features of this APK.

## Build

Open this `android` folder in Android Studio. Use JDK 17+, SDK Platform 36, Build-Tools 36.0.0, Gradle 8.13, AGP 8.13.2 and Kotlin 2.2.20. Versions are pinned in source. The Mac helper is `../Build-Android.command`.

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

The APK is `app/build/outputs/apk/debug/app-debug.apk`. Android package `com.tejasvi.campus.pilot` is a **debug testing package**, distinct from the release application ID. It is not a Play Store release. No production signing key or Play credentials are supplied. A build on another computer normally uses a different debug signing key; Android will refuse an in-place replacement signed by a different key. Keep the original APK for this pilot. Do not uninstall until local drafts are submitted or copied, because uninstalling removes device data.

## Data and sessions

Device tokens are generated by the server. Access tokens expire after 15 minutes; refresh tokens rotate with an absolute 30-day lifetime. MySQL stores their SHA-256 digests. A parent session links device revocation to existing password resets. Institution membership and class access are checked by the existing server rules on each operation. Mobile never connects directly to MySQL.

Credentials and assignment text drafts are encrypted with an Android Keystore AES-GCM key. Backup is disabled. Sign-out removes the local session, drafts and cached downloads. Institution switches clear downloaded files. Refresh is serialized; a failed write is never silently retried after a network or version-conflict error. If the server cannot confirm a submission, keep the draft and refresh Tasks before retrying to see whether it was received. Uploaded attachment selection is in memory; reselect it after closing the app.

Files are downloaded with authorization into private cache and shared temporarily with a chosen document viewer. Third-party viewers can retain files after opening. External HTTPS links receive no Tejasvi token. Redirects are not followed by the authenticated API client. All production traffic requires HTTPS; never add a trust-all TLS implementation.

## API contract

`status`, `auth/login`, `auth/refresh`, `auth/logout`, `auth/change-password`, `bootstrap`, `workspace?org=`, `units?course=`, `learning`, `assessments?course=&all=1`, `resources?course=`, `material?id=`, `submission-file`, `progress?org=`.

Only the native workflow's explicit mutations are exposed through this version. Browser write endpoints retain their original origin and CSRF checks. The server migration is `025_mobile_sessions.sql`; the normal launcher applies it to the original database. No new institution or database is required.
